What the analysis says about the revision (read before editing)
======================================================================

1. THE REVISION IS CONTAINED IN FILES WE OWN.

   gateVerdictFor  5 direct callers: Gate + 4 tests, all in internal/sem/gate.go
                   and internal/sem/gate_test.go. 0 callees. No caller outside
                   internal/sem.
   Gate            5 direct callers: runGate (internal/cli/gate.go:164) + 4 tests.
                   The single production path is Run -> runGate -> Gate.
   gateReach       3 direct callers: Gate, plus the teammate's own test helper
                   reachRun and TestReachLabelsTheMirrorRouteDistinctly.

   Every caller of the two functions the revision changes lives in a file the
   handover assigns to us. Nothing under internal/sem/ other than gate*.go is
   implicated, so the no-regression rule on the provider holds by construction.

2. GRADING NEEDS NO EDIT TO THE TEAMMATE'S FILE.  <-- the coordination question

   gateReach's callees include gateReachRoute (internal/sem/gate_reach.go:298),
   which already returns exactly "edge" / "mirror" / "name", and its type
   consumers show it RETURNS_TYPE gateReachedTest -- a type declared on OUR side
   of the seam, at internal/sem/gate.go:151, carrying the Route field.

   So the evidence classes the revision must grade are already produced and
   already cross the seam. Mapping route -> grade (edge=confirmed,
   mirror|name=heuristic, no-tests=unverified) is a pure function of data
   gate.go already receives. internal/sem/gate_reach.go does not need to change,
   and we will not touch it.

3. PARTIALITY DETECTION EXTENDS AN EXISTING PATTERN, IT DOES NOT INVENT ONE.

   Gate's callees already include gateRelationAdvertised (gate.go:359), which
   reads snapshot.Header.RelationSet to decide TestsRelationAvailable -- the
   existing precedent for "the header tells us how complete the input is".
   Gate already copies snapshot.Header.Warnings into the result. The fields
   CURVEBALL.md point 2 names all exist: Header.PartialFailures
   (provider.go:245), Header.Warnings, Header.LanguageTiers (provider.go:236,
   value "inventory-only" at provider.go:712).

4. THE FALLBACK COMMAND IS ONE FUNCTION, ON OUR SIDE.

   gateGoTestCommand (internal/cli/gate.go:240) builds the
   `go test -run '^(A|B)$' ./...` alternation. Point 3's widening is a change to
   that one function plus its caller, both in internal/cli/gate.go.

5. WHAT THE BLAST RADIUS WARNS ABOUT.

   gateVerdictFor has 4 dedicated tests and Gate has 4 more that reach it
   transitively. Changing gateVerdictFor's signature breaks 8 named tests at
   once. Point 4 requires fully-resolved behaviour to stay byte-identical, so
   those 8 are the regression surface: they must keep passing UNCHANGED, and a
   new signature must be additive rather than a rewrite of the existing one.

   Co-change coupling confirms the working set: internal/sem/gate.go has changed
   together with internal/cli/gate.go, internal/cli/gate_test.go and
   internal/sem/gate_test.go in 2 recent commits. Those four files are the
   expected footprint of this revision. A diff that reaches outside them is a
   signal to stop.
